# Horisma scientist identity and terminology data dictionary extension

Version:0.2.0. Date:2026-11-05. Status: IMPLEMENTED_CANDIDATE_ADAPTER_NOT_HISTORICAL_QUALIFICATION.

This versioned extension accompanies the unchanged [core0.1.0 dictionary](Horisma_Project_Data_Dictionary_EN.md), [person/name contract](../../spec/extensions/person_names.yaml) and [term relation contract](../../spec/extensions/term_aliases.yaml). New fields below are introduced in extension0.2.0; common provenance/missingness requirements are inherited unless explicitly specialized. Current project entry: [dictionary index](README.md).

### Scientist information extension0.2.0: sourced profiles, names and mentions

This extension applies the common provenance, missingness and disclosure obligations to the candidate adapter. It does not amend frozen core codes. Grain is one person profile, one source-reported attribute, one name-form observation, or one unchanged textual mention as specified below. Scientific review means a task-qualified automated producer in the current lane; no mandatory human evidence adjudication is introduced. No current adapter output is qualified identity evidence.

`PARTIAL_SOURCE_REPORTED_CANDIDATE` profiles contain available observations and explicit gaps. A profile aggregates assertions; it must not collapse conflicting statements into a single authoritative biography. Neither a preferred display name nor a generated portrait identifies a person. All fields below are introduced in extension0.2.0, have no numerical unit unless stated, and inherit source/record versioning. Logical links align with core L03/L05/L12/L32; these are implementation obligations, not completed formal proofs.

Current imported observations include birth/death time and place, citizenship, source-reported sex-or-gender, employment, education, awards, occupations and fields. They are separate assertion grains. Source property P21 is retained as `SEX_OR_GENDER_AS_REPORTED_UNDISAMBIGUATED`; it is not automatically mapped to sex assigned at birth, gender identity or preferred pronouns. Affiliation is not nationality. Kinship, sensitive private details and addresses are not inferred. Source biographical dates retain original calendar and precision; normalization into the full TemporalExtent model remains a separate adapter requirement.

Current coreference is an English conservative rule baseline. Given/family-only matches need scoped full-form context; same-name alternatives and unresolved observations stay potential antecedents. Gender is not inferred. First-person candidates require a known speaker and source-evidence references; the document author is not automatically the speaker inside quoted text. Non-English coreference, general syntax resolution, cataphora, collective referents and calibrated semantic qualification remain unimplemented.

Flag grain is one candidate citizenship→country→ISO→local-asset association. `person_ref`, `citizenship_assertion_ref`, `country_entity`, `iso_alpha2`, `iso_source_blob` and `iso_source_pointer` preserve the two source links. `path`/`sha256` bind the local SVG under Country-flags/flag-icons-main; `library_version`, `license_path` and `license_sha256` retain asset custody. These fields are nominal, required when an asset exists, and INTERNAL/RESTRICTED until release. `valid_time=null` and `historical_appropriateness=NOT_ESTABLISHED` prohibit asserting a current flag represents an entire life. `display_eligible=false` is current state. Multiple citizenships retain multiple associations; absent historical codes/assets remain missing rather than guessed. The library is a display resource, never biographical evidence.

Target terminology uses the same surface-form/mention primitive with a concept reference, but distinct concept semantics. [term_aliases.yaml](../../spec/extensions/term_aliases.yaml) owns candidate label/same-concept/related-mechanism/unresolved-sense relations. Translations and abbreviations require source observations; no generated equivalent is labelled attested. Accumulated/cumulative advantage remain related-mechanism candidates rather than automatic Matthew-effect aliases. All Matthew forms stay in the same development concept family; multilingual copies and correlated OCR channels do not enlarge the independent sample count. Lexical matching does not determine the intended sense, historical naming role or contribution priority.
