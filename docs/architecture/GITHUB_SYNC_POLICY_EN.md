# GitHub synchronization during the immature pipeline phase

2026-11-04. Owner steering: avoid spending main-model tokens on frequent remote synchronization before the research pipeline is mature.

Default to local iteration. Keep evidence, code, English documentation and project skills consistent locally; a small edit is not a release event. Make local checkpoints when useful. Earlier requests for timely GitHub updates do not imply a push after each change.

Synchronize remotely on an explicit current request or a named acceptance milestone that produces a coherent, reviewable bundle. Batch related implementation, tests, documentation and skills into one meaningful synchronization. A tiny schema edit or an optional model smoke check does not by itself complete a scientific milestone. Keep technical success separate from evidence/rights/transcription/adjudication acceptance.

Use deterministic scripts and existing Git/GitHub tools for file selection, credential-safe publication, hash checks and bounded retries. The main model should receive a concise outcome and material failures, rather than re-reading unchanged files or narrating each transport operation. For a required CI run, prefer one bounded completion watcher with a compact result over repeated conversational polling.

Continue to exclude private sources, raw extraction, real model attempts and unadjudicated evidence from technical exports. Preserve exact frozen contract versions and prior candidate revisions. Updating this policy locally is not itself a reason for another remote push.

Current work priority is the core evidence/adjudication slice and its independent acceptance. Additional components and repeated publication should not displace that work. The PFLM prototype remains disabled for automatic filtering pending task-quality evidence.
